# V32.1-18 P0 — desktop turns loop, fail, or remain busy

## User impact

On 2026-08-28, multiple desktop sessions using `openai-codex / gpt-5.6-sol`
performed excessive discovery for simple questions and then failed without a
useful final answer. This was not a Claude or Advisor failure.

## Proven V32.1-18 failure

Machine logs contain three independent `TurnBudgetExceeded` crashes. The newest
turn attempted model call 13 after 11 completed model rounds and 17 tool
results. The downstream V32 governor raised before the provider call. Its
`except TurnBudgetExceeded` handler belonged to a later, different `try` block,
so the exception escaped the conversation loop and reached the gateway.

The locked V33 upstream engine does not contain that downstream governor and it
is deliberately not ported.

The apparent Claude warning was a separate auxiliary-title symptom, not an
OpenAI turn being rerouted. The 15:44 session was configured for Claude; the
later failing sessions were persisted as `openai-codex / gpt-5.6-sol`. V32 also
charged the background title call to the same 12-call governor, reducing the
budget available to the user turn. V33 removed that governor and its shared
title context, so neither behavior is ported.

## Additional V33 lifecycle defect found during review

In the upstream desktop gateway, turn setup could fail before the local history
snapshot was assigned. The `finally` block then called `history.clear()`, raised
`UnboundLocalError`, and skipped `session.running = false`. Other unprotected
cleanup calls could also skip that settlement bookend. Later prompts in that
session were queued behind a dead turn.

## V33 correction

The `interactive-turn-reliability` engine hotfix:

- scales investigation depth to the request and stops broad product research
  once one authoritative result answers a simple question;
- assigns a deterministic budget without spending another model call on
  classification: high-confidence simple questions get at most 4 model rounds,
  ordinary turns 12, and explicit multi-step, attachment, synthesized, or
  active-goal work up to 30. A legacy `agent.max_turns: 500` profile cannot
  bypass those safety tiers; smaller `agent.max_turns` or
  `HERMES_TUI_MAX_TURNS` values tighten every tier, while background/CLI work
  keeps its own configured limit;
- makes `running = false` a non-skippable settlement boundary, with regression
  coverage proving that the next prompt in the same session can run.

## Desktop transport review

The 28 historical `socket hang up`, `ECONNRESET`, and 60-second timeout errors
in `desktop.log` occurred under V32.0-1. The locked V33 upstream already carries
separate keep-alive pools and verb-safe bounded retries for reset errors. One
gap remained: the Electron timeout was a plain `Error`, so the retry classifier
could not recognize it. The `desktop-transport-timeout` edition seam now tags
that exact failure `ETIMEDOUT`: a GET can use the existing bounded retry, while
a POST whose body was sent is never replayed.

A live loopback probe on 2026-08-29 received an HTTP response from the installed
backend port, so the available evidence does not show a dead global engine.
The proven failure mode is repeated per-turn over-investigation followed by a
bad governor exception, compounded by sessions that cleanup could leave busy.

## Release status

This incident keeps V33 at NO-GO for Latest until the materialized source gates,
desktop build, disposable-profile chat/relaunch smoke, and rollback gates are
green. No installed profile or public release is changed by this patch alone.
